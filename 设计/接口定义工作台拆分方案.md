# 接口定义工作台拆分方案

## 目标

将 `src/widgets/api-interface-workspace/ApiInterfaceWorkspace.vue` 中的「接口定义 / 接口管理」分支独立为 `ApiDefinitionWorkspaceModule.vue`，先完成物理边界切割，再做模块内部二次拆分。

第一阶段只做结构迁移，不改变现有业务行为、接口协议、页面交互和视觉样式。

## 核心原则

- 先整包平移，后内部拆解。
- 先定义输入输出契约，再迁移状态和逻辑。
- 父组件最终只负责顶级 Tab 容器和跨模块调度。
- 新模块第一版允许偏大，但必须形成清晰边界。
- 每个目标包完成后必须做类型检查和最小回归验证。
- 不回退、不覆盖用户已有改动，只基于当前代码做增量修改。

## Props 契约

第一阶段建议 `ApiDefinitionWorkspaceModule.vue` 接收以下 props：

```ts
interface Props {
  workspaceCode: string
  workspaceReady?: boolean
  workspaces?: WorkspaceItem[]

  environments: ApiRunEnvironmentItem[]
  variableSets: ApiVariableSetItem[]
  runOptionsLoading?: boolean
  runOptionsErrorMessage?: string
}
```

说明：

- `workspaceCode` 是目录、接口、用例加载的核心上下文。
- `workspaceReady` 用于避免工作空间未准备好时提前请求。
- `workspaces` 用于展示当前空间名称、判断全部空间、创建接口时选择归属。
- `environments`、`variableSets` 第一阶段暂留父级加载，因为场景、执行页后续也可能复用运行环境列表。
- `selectedEnvironmentId`、`selectedVariableSetId`、`selectedMockBusinessScenarioId` 第一阶段可先迁入 definitions 内部；如果后续要做全 Tab 统一环境选择，再提升到父级。

## Emits 契约

第一阶段必须保留：

```ts
interface Emits {
  loaded: [{ definitions: number; modules: number; cases: number }]
}
```

建议预留但第一阶段不强制实现：

```ts
interface Emits {
  definitionUpdate: [payload: { definitionId?: number; type: 'create' | 'update' | 'delete' }]
  caseUpdate: [payload: { definitionId?: number; type: 'create' | 'update' | 'delete' | 'run' }]
  runOptionsReload: []
}
```

说明：

- `loaded` 用于父级统计接口、目录、用例数量。
- `definitionUpdate` 后续用于同步场景页引用、执行页缓存和报告关联信息。
- `caseUpdate` 后续用于同步执行页、报告页。
- `runOptionsReload` 后续用于运行环境配置更新后通知父级重新加载环境列表。

## Watch 和生命周期归属

迁入新模块：

- 监听 `workspaceCode`，重新加载接口目录和定义数据。
