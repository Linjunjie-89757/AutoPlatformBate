## Path 参数执行闭环

- 现状：Swagger/OpenAPI 导入的路径参数会保留为 `/detail/{id}`，运行时只替换 `{{变量}}` / `${变量}`，不会自动替换 `{id}`。
- 风险：如果用户没有手动把 `{id}` 改成真实值，执行时会在 `URI.create()` 报非法路径。
- 后续优化：导入时把 `in: path` 参数转成可填写的路径参数；复制到场景/用例时保留；执行前用填写值替换 `{id}`，未填写时提示“路径参数 id 必填”。

- 风险：用户看到按钮会误以为可以单独运行某一步，但点击后不会有任何执行反馈。

- 当前详情接口只返回计划用例的最新执行结果，没有“执行历史列表”接口。执行历史 Tab 暂只能展示最近一次记录；后端需提供执行记录 ID、结果、实际结果、备注、执行人、执行时间和证据列表后再完成多次执行历史。
- 最新复制计划弹窗允许选择目标版本并复制需求范围，但需求属于原版本，跨版本不能直接复用原需求。当前后端会拒绝“跨版本 + 复制需求范围”，需产品/Figma 明确是重新选择目标版本需求、复制成新需求，还是自动关闭该选项。
- 最新创建缺陷抽屉没有“关联用例”选择控件，但现有测试计划缺陷必须绑定失败或阻塞的计划用例。执行工作台会自动绑定当前用例；从计划缺陷 Tab 打开时当前暂选第一条失败/阻塞用例。后续 Design 需明确计划级入口的目标用例选择方式，或取消无上下文的入口。
- Make 为“已取消”计划提供删除入口，而后端只允许删除草稿，以保护执行、缺陷和审计历史。当前以后端安全规则为准；若产品确认允许删除已取消计划，应先定义软删除与历史追溯规则，再调整 Design 和接口。
