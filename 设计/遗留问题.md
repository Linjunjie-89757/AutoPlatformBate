# 遗留问题

## Figma 视觉迁移 - 选择工作区

- 工作区卡片成员数、上次访问时间、角色名称、最近访问状态目前缺少完整后端字段契约。
- 当前处理：为了先对齐 Figma 设计，前端在字段缺失时使用 Figma 示例值兜底，例如 `8/12/5 名成员`、`今天 09:31/3 天前/7 天前`、`测试负责人/测试工程师/只读访客`。
- 后续优化：`/workspaces/switchable` 建议补齐 `memberCount`、`lastAccessTime/lastAccessAt`、`roleName`、`current/isCurrent` 等字段，字段稳定后移除前端视觉兜底。
- 工作区创建 / 申请加入入口目前只有视觉按钮和提示，缺少产品流程与后端接口。
- 后续优化：明确入口行为，是跳转工作区管理、打开创建弹窗，还是进入申请加入流程；设计确认后补齐真实交互。
- 工作区选择页当前只按桌面 Figma 设计还原，移动端仅做基础不溢出适配，未做移动端 1:1 设计稿对齐。
- 后续优化：如果该页需要移动端正式使用，需要让 Figma 补移动端设计后再按稿还原。
- 工作区卡片高度为了贴近当前浏览器实际视觉，将卡片上下内边距从 Figma 原始 `21px` 微调为 `20px`。
- 后续优化：如果后续像素验收要求严格按 Figma 原始数值，应恢复为 `21px` 并重新截图确认。

## Figma 视觉迁移 - 工作台

- 工作台页面按 Figma `自动化测试平台设计 / node-id=1:190` 先完成视觉落地，当前统计数据、任务动态、关注事项、系统健康、即将执行、AI 洞察均使用 Figma 示例值兜底。
- 当前处理：`/` 路由从占位页切换为工作台总览页，选择工作区后无指定 redirect 时默认进入 `/`。
- 后续优化：需要补齐工作台聚合接口，建议按模块提供今日执行统计、通过率、进行中任务、待处理缺陷、AI 待审数量、最近执行记录、异常关注项、系统健康状态、即将执行计划和 AI 洞察。
- Figma 顶部展示 `工作台 · X-MAN · 2026-07-07`、`早上好，张程远`、`测试负责人` 等示例文案；当前页面会读取登录用户名和角色，其他工作区名、日期仍为视觉兜底。
- 后续优化：需要统一工作区上下文、当前日期、用户角色展示规则，避免真实用户进入后仍看到 Figma 示例上下文。
- 快捷操作、全部、查看报告、去评审、跟进、查看日志、查看完整 AI 分析等按钮目前只保留部分基础跳转或视觉按钮，没有完整业务流。
- 后续优化：逐个确认按钮目标路由、筛选条件、详情页参数和权限规则，再接入真实跳转。

## 场景步骤保存模型

- 当前处理：步骤抽屉点击保存时，会保存整个场景，保证用户修改步骤后直接运行能使用最新配置。
- 后续优化：后端可以新增单步骤保存接口，例如 `PATCH /api/automation/api/scenarios/{scenarioId}/steps/{stepId}`，只替换 `stepsJson` 中被编辑的步骤。
- 需要注意：单步骤保存要处理嵌套步骤、步骤排序、并发覆盖、场景版本冲突和保存失败提示。

## Path 参数执行闭环

- 现状：Swagger/OpenAPI 导入的路径参数会保留为 `/detail/{id}`，运行时只替换 `{{变量}}` / `${变量}`，不会自动替换 `{id}`。
- 风险：如果用户没有手动把 `{id}` 改成真实值，执行时会在 `URI.create()` 报非法路径。
- 后续优化：导入时把 `in: path` 参数转成可填写的路径参数；复制到场景/用例时保留；执行前用填写值替换 `{id}`，未填写时提示“路径参数 id 必填”。

## 接口场景步骤单步执行

- 现状：场景步骤列表中的执行按钮仅为界面预留，当前没有绑定点击事件，也没有后端单步执行接口闭环。
- 风险：用户看到按钮会误以为可以单独运行某一步，但点击后不会有任何执行反馈。
- 后续优化：要么先隐藏该按钮；要么补齐单步执行能力，前端传 `scenarioId + stepId/stepOrder + 运行上下文`，后端只执行指定步骤并返回请求、响应、断言和提取结果。
