# Figma 设计对齐方法

这是一套可复用的 Figma 设计还原流程，适用于后台系统、业务平台、数据表格、弹窗、抽屉和复杂交互页面。

核心原则：

> Design 决定最终长什么样，Make 说明应该怎么动，现有系统决定哪些业务必须保留，浏览器实际结果决定是否真的对齐。

## 1. 资料优先级

开始实现前，同时收集以下资料：

### Figma Design

作为最终视觉标准，重点确认：

- 页面结构和层级
- 节点尺寸、坐标和对齐关系
- 字体、字号、字重和行高
- 颜色、透明度、背景和边框
- 圆角、阴影和间距
- 表格列宽、行高和操作列
- 图标类型、尺寸和位置
- 弹窗、抽屉、空态和异常态

### Figma Make 代码

用于确认结构和交互意图，重点查看：

- 点击后的页面、弹窗或抽屉
- Hover、Focus、Active、Disabled 和 Loading 状态
- Tab、筛选、分页和下拉选择
- 表单校验、提交、成功、失败和重试
- 数据变化后的刷新和状态切换
- 长文本、内容滚动和响应式处理

Make 代码不能替代 Design 节点的最终渲染尺寸。Make 中的演示数据和空回调也不能直接当成真实业务能力。

### 当前项目代码

需要确认：

- 页面入口和路由
- 组件层级和公共组件
- 当前模板 DOM
- 当前 CSS 和主题变量
- 已有接口、数据模型和权限
- 已有状态流转和审计规则
- 用户已经做过的修改
- 旧项目残留的样式和逻辑

### 项目设计准则

用于统一：

- 字体和字号体系
- 颜色和状态颜色
- 按钮、输入框、标签、表格规范
- 弹窗和抽屉规范
- 间距、圆角和阴影
- 响应式和可访问性要求
- 截图、验收和遗留问题记录方式

推荐的判断优先级：

```text
Design 的视觉结果
> 项目设计准则
> Make 的结构和交互
> 当前项目已有业务能力
```

如果 Design 和 Make 不一致，必须记录差异来源和最终裁决，不能直接宣称“完全对齐”。

## 2. 开始前的页面盘点

先列出目标页面的完整组成：

- 页面外层布局
- 顶部标题、面包屑和操作区
- Tab 和当前选中态
- 搜索、筛选和排序
- 表格、分页和列设置
- 侧栏、目录树和固定区域
- 操作列、下拉菜单和 Tooltip
- 弹窗、抽屉和详情页
- 加载、空数据、错误和无权限状态
- 成功反馈、失败反馈和重试入口

然后建立三方对照表：

| 区域 | Design | Make | 当前代码 | 处理方式 |
| --- | --- | --- | --- | --- |
| 主按钮 | 尺寸、颜色、图标 | 点击行为 | CSS 和事件 | 修改视觉，保留真实业务 |
| 表格 | 列宽、行高、操作列 | 分页和交互 | 数据接口和状态 | 对齐视觉与真实数据 |
| 弹窗 | 宽度、位置、圆角 | 打开、关闭、提交 | 当前组件 | 补齐结构和状态 |
| 操作列 | 图标、尺寸、间距 | Hover、点击 | 当前事件 | 修复样式和交互 |
| 空态 | 插图、文字、按钮 | 进入和退出条件 | 条件渲染 | 以实际状态为准 |

这一步可以避免只修复一个明显按钮后，就误认为整个页面已经完成。

## 3. 视觉对齐清单

每个可见控件都要逐项核对：

- 宽度和高度
- 内边距、外边距和相邻间距
- `gap`、对齐方式和基线
- 字体族
- 字号
- 字重
- 行高
- 字间距
- 文本颜色和背景颜色
- 边框宽度、颜色和透明度
- 圆角和阴影
- 图标类型、尺寸、颜色和位置
- 文本是否换行
- 长文本是否挤压其它元素
- 控件是否保持固定尺寸，避免状态变化时布局抖动

必须记录三组值：

```text
Design 节点最终尺寸
Make 的原始参数和运行意图
Vue 页面浏览器 computed style 与 bounding box
```

不能只看 CSS 源码。最终验收以浏览器实际渲染结果为准。

### 常见遗漏

- 按钮文字竖向换行
- 图标加载失败后只剩空白块
- 操作列靠近分页时菜单被遮挡
- 下拉菜单被 `overflow: hidden` 或 `overflow: auto` 裁切
- 弹窗垂直位置与 Design 不一致
- 抽屉的滚动区域错误
- 长标题挤掉数字、标签或操作按钮
- Hover 只改变背景，没有同步改变图标或文字颜色
- 禁用状态仍然可以点击
- 全局 CSS 覆盖了局部尺寸
- 内容展示态和编辑态错误地共用固定宽度
- 选项控件隐藏了箭头，用户无法识别其可选择性
- 页面根节点高度链路不完整，出现底部空白或内容截断

## 4. 交互对齐清单

每个按钮、链接和可操作控件至少确认以下状态：

```text
默认
→ Hover
→ Focus
→ Active / 点击
→ Loading
→ 成功
→ 失败
→ 重试
→ Disabled
```

每个弹窗或抽屉还要确认：

- 由什么动作打开
- 关闭按钮行为
- 遮罩点击是否关闭
- `Esc` 是否关闭
- 未保存修改时是否二次确认
- 提交期间是否允许关闭
- 内容过长时由哪个区域滚动
- 提交失败后是否保留用户填写内容
- 成功后是否刷新列表或详情
- 浏览器返回、刷新和分享链接是否保留当前位置
- 重复点击是否被阻止
- 并发修改是否提示冲突

Make 代码可以补充静态 Design 看不到的动态行为，但需要先区分真实功能和演示回调：

- 有真实接口和持久化：可以接入
- 只有本地数组：只能作为交互参考
- 空回调：不能宣称功能已完成
- 演示数据：不能当成真实统计或状态

## 5. 问题分类和处理方式

发现差异后，分为视觉、交互和后端三类，不要混在一起处理。

### 视觉问题

例如字号、字重、颜色、尺寸、位置、间距、圆角和图标错误。

处理方式：修改目标页面的 DOM 或局部 CSS，避免随意修改全局公共组件。

### 交互问题

例如 Hover 没有变化、点击没有打开抽屉、菜单没有关闭、提交期间没有禁用、成功后不刷新。

处理方式：按照 Make 的交互意图补齐 Vue 事件、状态和组件行为。

### 后端问题

例如接口不存在、数据无法保存、权限未校验、状态流转没有服务端限制或缺少审计。

处理方式：保留正确的视觉和状态表达，但不能用假数据、假成功或前端数组掩盖后端缺口。需要在遗留问题中记录：

- 页面和节点
- 当前行为
- Design / Make 的表达
- 缺失的接口或数据能力
- 影响和风险
- 后续动作

## 6. 业务逻辑和视觉设计的边界

设计对齐不等于盲目复制 Make 的业务逻辑。

当 Design、Make 和现有业务规则不一致时：

1. 先确认用户已经明确的业务规则。
2. 识别 Make 是否只是演示实现。
3. 保留真实系统必须具备的闭环和数据安全约束。
4. 视觉上尽量复用 Design 的结构和状态表达。
5. 将无法实现的后端能力单独登记，不用假接口伪装完成。

例如，Design 中有“保存成功”，但当前没有真实保存接口时，可以实现提交中的视觉状态和失败提示，但不能在前端直接提示真实保存成功。

## 7. 控制修改范围

每次任务开始前明确：

- 只对齐哪个页面、弹窗或组件
- 只修改哪些文件
- 哪些用户已有改动不能碰
- 哪些业务逻辑保持不变
- 哪些差异明确不处理

执行过程中遵守：

- 只修改当前目标直接涉及的文件
- 优先复用项目已有公共组件和 token
- 不因为一个局部问题重构整个页面
- 不顺手清理无关旧代码
- 不覆盖或回退用户未提交的改动
- 中文源码使用小范围补丁修改，保护原始编码和换行

## 8. 验证流程

### 代码验证

根据改动范围运行：

- 类型检查
- 单元测试或接口测试
- 前端构建
- 后端测试
- `git diff --check`

### 页面验证

使用与 Design 相同的视口和尽可能一致的 DPR，检查：

- 页面首屏
- 页面头部
- 主要内容
- 侧栏和底栏
- 表格和分页
- 弹窗和抽屉
- 设计明确提供的空态或控制器态

### 状态验证

至少覆盖：

- 默认态
- Hover
- Focus
- 选中态
- Loading
- Disabled
- 空态
- 错误态
- 成功态
- 重试态

### 边界验证

- 长标题和长描述
- 窄屏
- 大量数据
- 操作菜单靠近页面底部
- 弹窗内容超长
- 下拉菜单靠近容器边界
- 多次快速点击
- 浏览器刷新和返回
- 无权限和登录失效
- 多人同时修改

### 证据记录

交付前保留：

- Figma Design 同状态截图
- 实际页面同尺寸截图
- 关键节点 computed style
- 关键节点 bounding box
- 交互状态和接口响应结果

只有 Design、Make 和实际浏览器结果都分别核对过，才可以使用“已对齐”或“完全一致”。否则应明确写成“已完成部分对齐”，并列出未验证项。

每次对齐完成后，建议使用以下格式记录：

```markdown

- 页面 / 组件：
- Figma 节点：
- Make 代码目录：
- 当前项目文件：
- 明确不处理：

## 已修复

### 视觉差异

-

### 交互差异

-

### 状态差异

-

## 保持不变

- 已确认的业务逻辑：
- 用户已有修改：
- 暂不接入的后端能力：

## 验证结果

- 类型检查：通过 / 未执行 / 失败
- 构建：通过 / 未执行 / 失败
- 接口测试：通过 / 未执行 / 失败
- 页面截图：已保留 / 未执行
- Hover、Loading、Error 等状态：
- 长文本和窄屏：

## 遗留问题

- 页面 / 节点：
- 当前行为：
- Design / Make 表达：
- 影响或风险：
- 后续动作：补设计 / 补前端 / 补后端 / 产品确认
```
