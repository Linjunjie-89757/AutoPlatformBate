# Figma 待补设计与视觉差异台账

> 更新日期：2026-09-01
> 适用范围：自动化测试平台 2.0 当前 Vue 路由、`设计/遗留问题.md`、`docs/frontend-adjustments-inventory.md` 和已登记的 Figma Design / Make 节点。
> 目的：把“实现没有按已有设计对齐”“现有业务能力缺少正式设计”“只缺异常状态稿”“历史记录已过期”分开管理。

## 1. 使用规则

### 1.1 状态定义

| 状态 | 含义 | 处理责任 |
| --- | --- | --- |
| 需实现修复 | 已有明确 Design / Make 基准，当前 Vue 仍存在可量化差异 | 前端修复并截图复核，不要求 Figma 重新设计 |
| 需 Figma 补稿 | 当前业务入口、弹窗、抽屉、详情或状态没有正式 Design 节点 | Figma 先补节点，前端再迁移 |
| 需产品决策 | 现有业务能力与最新设计取舍冲突，不能由前端自行决定 | 产品先确认保留、迁移或删除，再决定是否补稿 |
| 待视觉验收 | 已按 Make 或同风格延展实现，但缺少独立 Design 节点，不能声明 1:1 | Figma 补节点后逐状态验收 |
| 文档冲突 | 较早记录与较新 Design、Make 或产品结论不一致 | 以最新确认结果为准，关闭或改写旧记录 |

### 1.2 优先级

| 优先级 | 判断标准 |
| --- | --- |
| P0 | 阻塞核心创建、编辑、执行、保存或真实业务接入；或当前页面仍明显使用另一套视觉 |
| P1 | 高频管理流程、详情、批量操作、错误恢复或权限状态不完整 |
| P2 | 低频入口、移动端、轻微像素差异或增强型交互 |

### 1.3 信息优先级

发生冲突时按以下顺序判断：

1. 最新且已确认的 Figma Design 节点。
2. 最新 Make 代码表达的交互意图。
3. 当前 Vue 已接通的真实业务规则和后端约束。
4. `设计/遗留问题.md` 中较早的历史记录。

真实业务数据与 Figma 示例数据不同不属于视觉缺陷，不得为了截图一致修改真实数据。

### 3.7 接入方式与样式来源判定

这里要区分“业务接口是否接通”和“页面样式是否来自正式 Figma”。当前项目运行时没有直接依赖 Figma 文件组件；Vue 页面中的 DOM、class 和 CSS 都是本地代码。所谓“按 Figma 接入”，通常是依据 Figma Design 或 Make 的节点、截图和尺寸手工实现，再接入真实后端。

| 类别 | 项目 | 判定 |
| --- | --- | --- |
| 按 Figma / Make 规格修正 | `UI-001`、`UI-002`、`UI-003`、`UI-004`、`UI-005`、`UI-006`、`UI-009` | 不是旧项目样式；是本地 Vue/CSS 按 Design/Make 尺寸、布局或交互意图实现。其中 `UI-001` 是按目标尺寸修正，`UI-006` 的 `figma-result` 是本地新增变体，仍需截图级验收。 |
| 沿用已有 Figma 结构并接真实能力 | `FG-008`、`FG-009`、`FG-010`、`FG-011`、`FG-021`、`FG-028`、`FG-035`、`FG-036`、`FG-037` | 业务接口是真实接入，页面继续沿用已有 Figma DOM / class / 布局；缺失的弹窗、详情和异常状态由本地同风格延展，不能称为完整 Figma 1:1。 |
| Figma 风格延展，尚无独立节点 | `FG-006`、`FG-007`、`FG-014`、`FG-015`、`FG-018`、`FG-020` | 有设计语言或相邻页面作为参考，当前实现主要是本地延展；高级字段、异常态和完整交互仍需 Figma 补稿。 |
| 明确仍是旧项目视觉 | `UI-008`、`FG-004` 的数据库新增/编辑弹窗，以及配置中心环境新增弹窗 | 列表/主体可能已按 Figma 调整，但弹窗仍沿用旧项目前端视觉，不能算 Figma 接入完成。 |
| 无正式节点的自定义/临时实现 | `FG-001` 的新建/申请流程、`FG-025`、`FG-026`、`FG-029`、`FG-038` 的编辑/删除入口 | 真实功能或部分功能可能已经接通，但缺少对应 Figma Design，不能把当前样式当作最终设计；其中 `FG-038` 编辑/删除仍有演示提示。 |

因此，前面标记“功能已接通”的项目，含义是接口和业务链路已实现；只有明确写着“按 Figma / Make 规格修正”或“沿用已有 Figma 结构”的部分，才能说视觉参考了 Figma，且仍要以正式节点和截图验收为准。

## 6. Figma 补稿交付要求

每个补稿项至少应包含：

1. 可定位的 Design 节点链接和节点 ID，不只提供 Make 代码。
2. 默认、hover、focus、selected、disabled、loading、empty、error、success 状态。
3. 弹窗/抽屉的提交中、字段错误、接口失败、关闭确认和恢复默认态。
4. 表格的分页、无数据、搜索无结果、横向溢出和批量选中态。
5. 真实数据长度变化：长标题、长错误、字段缺失、数量为 0 和未知值 `—`。
6. 权限状态：无查看权限、无操作权限、按钮禁用与后端 403 反馈。
7. 至少一个桌面验收尺寸；面向公开访问或高频入口的页面还应给出窄屏稿。

## 7. 前端验收规则

补稿完成后，前端按以下顺序关闭台账项：

1. 获取确切节点的 Design Context 和截图。
2. 使用同一视口、同一业务状态采集 Vue 页面截图。
3. 对比尺寸、间距、字体、字重、边框、圆角、图标、浮层和状态变化。
4. 保留真实业务能力，不用 Figma 示例数据伪造成功或统计。
5. 运行类型检查、构建和相关交互测试。
6. 在本台账中将状态更新为“已实现待验收”或“已关闭”，并回写节点 ID、验证日期和截图位置。
