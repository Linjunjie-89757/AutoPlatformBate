## 工作区选择与基本配置功能接入待补齐明细

当前工作区选择页已经调用 `GET /api/workspaces/switchable` 展示账号真实可访问工作区，选中后会保存真实工作区上下文并恢复原目标路由；系统设置用户管理也已接入真实成员列表、添加、角色调整和移除接口。

后续仍需补齐以下前后端与设计差异：

- 工作区选择页“创建新工作区 / 申请加入其他工作区”目前只有 Figma 入口，点击仍提示后续接入。后台已有工作区创建接口，但当前入口没有对应的新建表单流程；后台也没有申请加入、审批、邀请状态和通知接口，不能把创建与申请合并成同一个假操作。
- 系统设置“基本配置”已接入真实工作区读取和更新接口：名称、描述会从当前具体工作区加载并真实保存；Figma 页面未展示的工作区类型、负责人和状态会在更新时原样保留，避免只编辑名称/描述时覆盖后台已有值。“全部工作空间”属于聚合视角，页面会清空可写名称/描述并阻止提交。
- Figma 页面中的默认执行环境、数据保留天数、企业微信通知开关和 AI 能力开关仍没有对应工作区字段。现有控件保留原设计位置与视觉，但交互会明确提示后台能力缺失，不再修改本地状态或随基本信息伪保存。
- 后台支持工作区删除、成员新增/更新/移除，但 Figma 基本配置页没有工作区删除、负责人转让、停用影响和二次确认的完整设计；不能直接复用旧项目弹窗破坏新前端视觉。
- 工作区选择卡片需要成员数、当前账号角色、最近访问时间和当前/默认状态。当前接口契约仍不能稳定提供全部字段，相关视觉兜底需要在后台补齐 `memberCount`、`roleName/roleCode`、`lastAccessAt`、`current/default` 后移除。
- “全部工作空间”是聚合视角，不是可写目标。新增、编辑、删除及成员变更必须要求明确的具体工作区，不能把 `ALL` 作为业务数据提交。

当前已明确暂缓“创建新工作区”接入，待 Figma 补充独立的新建工作区弹窗、字段、校验、提交中和成功后的切换流程设计后再实施，不在现有卡片入口上自拟旧项目表单。“申请加入其他工作区”仍需另外补申请、审批、通知和状态流转后台模型，不能与创建工作区共用一个假流程。

后续补齐时应分别实现“创建工作区”和“申请加入”两条真实流程；默认执行环境、数据保留策略和功能开关需要先明确归属配置模型并新增后台字段/接口。后台虽已有负责人、状态和删除能力，但当前 Figma 基本配置页缺少负责人转让、状态变更影响及删除确认的完整设计，补设计前不新增旧风格入口。

配置总览六张统计卡片已改为聚合真实数据库连接、测试环境、Runner 节点、个人 AI 连接、通知渠道和全局参数数据。数据库、环境、通知和参数的总数及启用数来自对应分页接口的 `total`，不依赖当前页数组长度；Runner 在线数按真实心跳离线标记计算，AI 卡片展示真实启用连接数、连接总数和已配置 Key 数。页面继续沿用现有 Figma 卡片 DOM、尺寸和 CSS。

当前总览与后台统计能力仍存在以下差异：

- 后台没有统一的数据库连接、通知渠道和 AI 连接测试历史接口，也没有按日期聚合成功/失败次数的统计接口。原固定 SVG 趋势线会被误认为真实数据，当前保留 Figma 图表容器、坐标轴、日期和图例，改为明确的无真实趋势数据状态。后续应新增按工作区和日期范围查询的测试历史聚合接口后再恢复曲线。
- 后台没有配置总览聚合接口。当前一次加载需要分别查询数据库、环境、参数、通知的总数与启用数，并读取 Runner 和 AI 连接列表，共 10 个轻量请求；工作区数据继续增长后应新增单一 `/settings/overview` 聚合接口，避免总览请求数量随统计项扩展。
- Runner 节点接口当前是平台全局数据，不按工作区过滤；AI 连接是当前登录用户个人数据，也不按配置中心工作区隔离。因此这两张卡片展示真实数据，但统计口径与数据库、环境、通知、参数四张工作区卡片不同。若产品要求统一工作区口径，需要先补 Runner/AI 的工作区归属模型。
- 后台没有配置统计快照或历史趋势，切换工作区时只能实时重新聚合当前状态，无法展示过去某日的配置数量。

本轮没有新增模拟统计、没有把列表当前页条数冒充总数，也没有为了真实数据接入调整 Figma 卡片布局。

## 配置中心 AI 连接配置功能接入遗留问题

当前 AI 连接配置页已接入真实连接列表、新增、编辑、删除、启停、已保存连接测试、未保存新连接模型列表预览、缓存模型列表、远端模型同步、单模型能力探测和默认模型切换。列表、统计、测试结果和模型抽屉不再回退到 Figma 示例连接、示例模型、固定响应耗时或按服务商类型推断的用途数据；页面现有 Figma DOM、抽屉尺寸和 CSS 保持不变。

当前 Figma 交互结构与后台 AI 连接契约仍存在以下差异：

- 后台没有连接级“默认评审模型”和“最大重试次数”字段，也没有能力标签人工配置接口。编辑抽屉保留现有控件，但点击或保存时明确提示不会持久化；列表能力标签只汇总真实缓存模型返回的能力探测结果。
- 后台没有“用例生成、用例评审、失败分析、元素识别、断言建议”的主模型/备用模型用途绑定模型。用途配置区统一展示未指定，保存按钮只提示缺少接口，不再自动把第一、第二个连接伪装成主备绑定。
- 后台支持远端模型同步和单模型能力探测，但没有手工新增模型、模型启停和模型删除接口。模型抽屉“添加模型”当前按真实远端同步能力执行；启停和删除按钮只提示能力缺口，不修改本地列表。
- 连接编辑态未填写新 API Key 时，后台无法使用已加密 Key 测试尚未保存的 URL、协议或模型修改。当前会明确提示并只测试已保存配置；填写新 Key 或新建连接时，通过 `/api/cases/ai/providers/preview-models` 验证当前 URL 和 Key 能否读取模型列表。后台后续若要验证完整聊天调用，应新增独立的草稿连接测试接口。
- 连接表只有 `status=0/1`，测试失败和管理员手工停用都会写成 `0`，列表无法可靠区分“异常”和“已停用”。后台也没有最近一次失败时间、失败原因和测试耗时字段；当前最近测试只展示最后一次成功验证时间，弹窗耗时只反映本次浏览器请求实测值。
- AI 连接当前按登录用户个人所有权查询，后台返回的 `workspaceCode` 为 `PERSONAL`，并不按配置中心当前工作区隔离。若产品目标是工作区共享连接，需要新增工作区归属、成员权限和迁移规则，不能仅依赖 `X-Workspace-Code` 请求头。
- 连接列表响应没有聚合能力字段。为展示真实能力标签，当前会按连接读取缓存模型列表，连接数量增长后会形成 N+1 请求；后台应在连接列表中补充已探测能力摘要，或提供批量模型摘要接口。
- 模型接口未返回统一的上下文长度字段，只有部分服务商原始元数据可解析。无法确认时模型抽屉显示 `—`，不再默认展示虚构的 `128K`。

本轮没有扩展后台模型、没有伪造用途绑定或模型状态，也没有为了功能接入调整 Figma 页面布局和视觉样式。

## 迁移验收方式

每迁移一个页面，固定：

- 路由
- 账号/权限
- 工作空间
- 数据状态
- 浏览器缩放 100%
- 视口 `1366x768` 和 `1920x1080`

对比：

- 页面外边距
- 卡片宽高和间距
- 字号/字重/行高
- 按钮高度、圆角、hover
- 表格行高、表头、固定列
- 弹窗/抽屉 header/body/footer
- 空状态/加载态/错误态
- 横向/纵向滚动行为

结论：

旧前端已经值得迁移的不是“大文件代码”，而是这些被反复调过的视觉规则、交互状态、业务链路和页面验收标准。前端 2.0 应该复刻结果，而不是复刻旧代码组织。
